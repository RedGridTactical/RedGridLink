# V1.4 Design — Extended Range + Android Production

**Date:** 2026-03-28
**Status:** Approved
**Milestone:** V1.4 — Android Launch + Extended Range (Q3 2026)

## Summary

V1.4 adds 5 features: BLE Long Range (Coded PHY) for 400m-1km range, connection quality indicators, FixPhrase 4-word location encoding, OpenStreetMap offline tile downloads, and Android production release. F-Droid deferred to v1.5.

## Features

### 1. BLE Long Range (Coded PHY)

**Goal:** Extend Field Link range from ~30-50m to 400m-1km using BLE 5.0 Coded PHY.

**Approach:** Native platform channels (no flutter_blue_plus fork).

**Android (Kotlin):**
- New method channel: `com.redgrid.link/ble_phy`
- Methods: `requestCodedPhy(deviceAddress)`, `isCodedPhySupported()`, `getCurrentPhy(deviceAddress)`
- Implementation: `BluetoothGatt.setPreferredPhy(PHY_LE_CODED, PHY_LE_CODED, PHY_OPTION_S8)`
- S8 coding = maximum range (~4x standard BLE), 125 kbps throughput
- Requires Android 8.0+ (API 26) and hardware support
- Runtime check: `BluetoothAdapter.isLeCodedPhySupported()`

**iOS (Swift):**
- CoreBluetooth auto-negotiates Coded PHY when both devices support it (iPhone 8+, iOS 14+)
- No explicit PHY selection API — detect active PHY from connection events
- Lighter implementation than Android

**Dart layer:**
- New `BlePhyService` wrapping platform channels
- `BleTransport` calls `requestCodedPhy()` after successful connection
- Silent fallback if device doesn't support Coded PHY
- Expose `isLongRange` boolean per peer connection

**UI:**
- "LR" badge on peer cards when Coded PHY is active
- Info tooltip explaining range improvement

**Trade-off:** Coded PHY S8 halves throughput (125 kbps vs 1 Mbps). Acceptable for position updates (<200 bytes). Large payloads use P2P transport which is unaffected.

### 2. Connection Quality Indicator (RSSI)

**Goal:** Live signal strength display for each connected peer.

**Approach:** Extend existing RSSI infrastructure (currently one-shot during discovery).

- Add periodic RSSI polling timer: every 5 seconds per connected peer
- Rolling average of last 5 readings to smooth fluctuations
- New `connectionQualityProvider` (Riverpod StateNotifierProvider) keyed by peer ID
- 4-tier signal display (reuse existing color bar widget from `SessionJoinCard`)
- Range warning: notification when any peer drops below -85 dBm for 3+ consecutive readings

**Display locations:**
- Peer HUD overlay on map
- Team roster bottom sheet
- Session status bar

### 3. FixPhrase (4-Word Location Encoding)

**Goal:** Encode any lat/lon as 4 hyphenated English words (~11m accuracy). Order-independent.

**Approach:** Port from RedGridMGRS JavaScript implementation to Dart.

**Algorithm:**
1. Shift coordinates to positive integers: `latInt = (lat * 10000 + 900000).round()`, `lonInt = (lon * 10000 + 1800000).round()`
2. Convert to 7-digit zero-padded strings
3. Extract 4 groups with non-overlapping index ranges:
   - g0: 0-1999 (latitude high bits)
   - g1: 2000-5609 (longitude high bits)
   - g2: 5610-6609 (mid-precision)
   - g3: 6610-7609 (full precision)
4. Map each group index to wordlist

**Precision modes:**
- 2 words: ~1.1km accuracy
- 3 words: ~110m accuracy
- 4 words: ~11m accuracy

**Key property:** Words can be provided in ANY order due to non-overlapping index ranges.

**Assets:**
- `assets/fixphrase_wordlist.json` — 7,611 English words (BSD-3-Clause, Netsyms Technologies)

**Files:**
- `lib/utils/fixphrase.dart` — encode/decode functions
- Integration into Coordinate Converter tool
- Integration into coordinate display format selector

### 4. OpenStreetMap Offline Tile Source

**Goal:** Allow downloading OSM tiles for offline use (currently only OpenTopoMap downloadable).

**Approach:** Minimal change to existing tile infrastructure.

- `TileSources.osm` already works for online viewing
- Add `tileSource` parameter to `TileManager.downloadRegion()`
- Update `MapDownloadSheet` with source selector (OSM / OpenTopoMap / USGS Topo)
- Store source type in `MapRegion` database row for correct attribution when viewing offline
- ~30 lines of logic change, mostly UI

### 5. Android Production Release (DEFERRED)

**Deferred until LLC/business account conversion.** Once Estus Holdings LLC is approved and both Apple (ASC) and Google (Play Console) accounts are converted to business/organization accounts, promote to Production track. This bypasses TestFlight external tester review on iOS and provides proper business identity on both stores.

### 6. F-Droid (DEFERRED to v1.5)

**Rationale:** F-Droid requires removing Google Play Services (Nearby Connections API) and Play Billing. This is a significant architecture change that would block the v1.4 production launch. Better as a dedicated effort.

## Implementation Order

1. **FixPhrase** — Pure Dart, no platform risk, immediately testable
2. **OSM tile source** — Small change, high user value
3. **Connection quality indicator** — Wiring existing pieces
4. **BLE Long Range (Coded PHY)** — Native platform work, highest complexity

Android production release deferred until business account conversion.

## Non-Goals

- F-Droid submission (v1.5)
- Meshtastic integration (v2.0)
- ATAK interoperability (v2.0)
- Route planning (v2.1)

## Testing Strategy

- Unit tests for FixPhrase encode/decode (round-trip, edge cases, word order independence)
- Unit tests for RSSI rolling average and threshold logic
- Widget tests for connection quality display
- Integration tests for Coded PHY platform channel (mock channel responses)
- Manual testing: two physical BLE 5.0 devices for Coded PHY range verification
