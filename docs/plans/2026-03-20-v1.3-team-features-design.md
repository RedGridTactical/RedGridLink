# V1.3 Team Features — Design Document

**Date:** 2026-03-20
**Status:** Approved
**Target:** Q3 2026

## Overview

V1.3 adds team coordination features to Red Grid Link: roles, shared waypoints, tap-to-place annotations, geofence boundaries, enhanced AAR, new marker categories, NATO voice callouts, and session export/import.

All features build on the existing CRDT sync engine and Riverpod state management. No new transport protocols or database migrations beyond adding columns.

---

## 1. Team Roles

### Data Model

Add `role`, `callsign`, and `customRoleLabel` to `Peer`:

```dart
enum TeamRole { lead, scout, medic, comms, custom }

// Peer additions:
final TeamRole role;              // default: scout
final String callsign;            // user-chosen display name
final String? customRoleLabel;    // only when role == custom
```

### Sync

- Role assignment flows as `SyncPayloadType.control` messages
- Only the Lead can send role-change control messages
- Session creator is auto-assigned Lead
- Lead can promote any peer to Lead (transfers role, demotes self to Scout)

### Enforcement

Role is advisory, not permission-gated. Any peer can place markers and draw annotations. Lead distinction only matters for: boundary creation, role assignment, and future features.

### UI

- Session roster screen shows each peer with role icon + callsign
- Lead sees "Manage Roles" option per peer
- Map peer markers show role-specific icons

## 2. Waypoint Sharing

### Two Paths

**Personal waypoints** (unchanged):
- SharedPreferences via `WaypointRepository`
- Persists across sessions, local only
- Managed through `waypointListProvider`

**Shared waypoints** (new):
- Bottom sheet on waypoint create/tap: "Save to My Waypoints" and "Share with Team"
- "Share with Team" creates a `Marker` with `MarkerOrigin.sharedWaypoint` and pushes through CRDT as `SyncPayloadType.marker`
- Session-scoped, disappears when session ends
- Users can save locally AND share in one action

### Data Model

```dart
enum MarkerOrigin { manual, sharedWaypoint }

// Marker addition:
final MarkerOrigin origin;  // default: manual
```

### Wire Format

Adds `"o": "sw"` to marker payload. One byte, stays under 200.

### Map Rendering

Shared waypoints render with a distinct icon (waypoint pin with broadcast indicator).

## 3. Shared Annotations (Tap-to-Place)

### Interaction Flow

1. User taps annotation toolbar (existing `annotation_toolbar.dart`)
2. Selects mode: Polyline or Polygon (existing `DrawingMode` enum)
3. Each map tap adds a vertex to `drawingPointsProvider`, preview renders in real time
4. User taps "Done" to finalize. Annotation created locally and broadcast via CRDT
5. All peers see it through `syncedAnnotationsProvider`

### Existing Infrastructure

- `DrawingMode` enum, `drawingPointsProvider`, `annotation_layer.dart`, CRDT annotation sync with LWW + tombstones all exist

### New for V1.3

- **Color picker:** 6 preset tactical colors (red, blue, green, yellow, orange, white)
- **Label input:** optional text label on finalize (e.g., "Search Sector A")
- **Undo last point:** pops last entry from `drawingPointsProvider` during drawing
- **Delete annotation:** tap existing annotation to select, show delete option, sends tombstone

### No new models needed

Existing `Annotation` model already has `color`, `label`, `points`, `createdBy`, `isSynced`.

## 4. Team Boundary Alerts (Geofence)

### Data Model

Extend `AnnotationType`:

```dart
enum AnnotationType { polyline, polygon, boundary }
```

### Creation Flow

1. Only Lead can create a boundary (UI hidden for other roles)
2. Lead taps "Set Boundary", draws polygon via tap-to-place
3. Syncs as annotation with `type: boundary` through existing CRDT path
4. Rendered as dashed outline with subtle fill (visually distinct)
5. One boundary per session. New boundary tombstones the previous

### Geofence Check

- Runs on every position update (piggybacks on `positionStreamProvider`)
- Point-in-polygon ray casting algorithm
- Maintains `wasInsideBoundary` boolean per peer to detect crossings
- Only triggers on state transition (inside to outside), not continuously

### Notifications (Option B)

- **Member who crossed:** local notification + on-screen banner "You left the team boundary"
- **Lead:** receives control message "Scout-3 left the boundary" with timestamp and position

### Wire Format

```json
{
  "t": "control",
  "s": "peerId",
  "d": { "evt": "boundary_exit", "lat": 35.1, "lon": -79.0 }
}
```

### Edge Cases

- Lead disconnects: boundary persists in CRDT. No new boundary until new Lead promoted
- Peer already outside when boundary created: immediate alert
- Checks are local. Each device runs ray casting against own position. Exit sends control message to Lead

## 5. Enhanced AAR (PDF)

### New PDF Content

1. **Team roster with roles:** cover page shows each peer with role icon, callsign, connection duration
2. **Per-member track summary:** distance, time active, area covered per peer (not one combined track)
3. **Boundary overlay:** boundary polygon on map snapshot + boundary exit events table
4. **Role labels on markers:** each marker shows callsign and role, not raw peer ID

### Data Model Changes

```dart
// TrackPoint addition:
final String peerId;

// AarData additions:
final Annotation? boundary;
final List<BoundaryEvent> boundaryEvents;

class BoundaryEvent {
  final String peerId;
  final String callsign;
  final DateTime timestamp;
  final Position position;
}
```

### No Interactive Replay

Deferred to V2.1 alongside route planning and freehand drawing.

## 6. Custom Map Marker Categories

### Consolidated Enum

```dart
enum MarkerIcon {
  waypoint,     // generic nav point
  hazard,       // danger/warning (consolidates old 'danger')
  camp,         // campsite/shelter
  rallyPoint,   // assembly/meetup (consolidates old 'rally')
```

### Migration

Persisted markers with old `danger` or `rally` values mapped to `hazard` and `rallyPoint` on read. One-line mapping in Drift DAO.

### UI

Marker placement bottom sheet shows a grid of icons with labels. Simple tactical symbols (Flutter icons or custom SVG).

## 7. Voice Callout Queue

### Behavior

- On incoming peer position sync, optionally announces in NATO phonetic alphabet
- Callouts queued, not overlapping. Each finishes before next starts
- Debounced: one callout per peer per 30 seconds max
- Fires when a peer's MGRS grid square changes (first 6+ chars differ from last announced)

### NATO Digit Pronunciations

| Digit | NATO |
|-------|------|
| 0 | ZE-RO |
| 1 | WUN |
| 2 | TOO |
| 3 | TREE |
| 4 | FOW-ER |
| 5 | FIFE |
| 6 | SIX |
| 7 | SEV-EN |
| 8 | AIT |
| 9 | NIN-ER |

### Implementation

- `flutter_tts` package for text-to-speech
- Two lookup maps: letters (Alpha, Bravo...) and digits (above)
- Toggle setting: on/off (default off)

### Service

```dart
class VoiceCalloutService {
  final Queue<String> _queue;
  bool _isSpeaking;

  void enqueue(String callsign, String mgrs);
  void _processQueue();
  void stop();
}
```

### Providers

- `voiceCalloutEnabledProvider` (StateProvider<bool>)
- `voiceCalloutServiceProvider` (Provider<VoiceCalloutService>)

## 8. Export/Import Session Data

### Export Format

```json
{
  "version": "1.3",
  "exportedAt": "2026-07-15T14:30:00Z",
  "session": { "id", "name", "mode", "createdAt" },
  "peers": [{ "id", "callsign", "role", ... }],
  "markers": [{ ... }],
  "annotations": [{ ... }],
  "boundary": { ... },
  "boundaryEvents": [{ ... }],
  "trackPoints": [{ "peerId", "lat", "lon", "timestamp", ... }]
}
```

### Export Flow

1. After session ends (or from session history), tap "Export Session"
2. Serialize all session data from Drift into JSON
3. `share_plus` opens system share sheet

### Import Flow

1. Tap "Import Session" from session history
2. File picker, select `.json` file
3. Validate version field and structure
4. Import into Drift as read-only historical session
5. Viewable in session history, can generate AAR from it

### Validation

Check version, required keys, coordinate bounds (-90/90 lat, -180/180 lon). Reject malformed files with clear error.

### File Naming

`redgridlink_session_<name>_<date>.json`

## Database Migration (Schema v3)

### Peers table additions

- `role` TEXT DEFAULT 'scout'
- `callsign` TEXT DEFAULT ''
- `customRoleLabel` TEXT nullable

### Markers table additions

- `origin` TEXT DEFAULT 'manual'

### Annotations table changes

- `type` now accepts 'boundary' in addition to 'polyline', 'polygon'

### TrackPoints table additions

- `peerId` TEXT DEFAULT ''

### New table: BoundaryEvents

- `id` TEXT PK
- `sessionId` TEXT FK
- `peerId` TEXT
- `callsign` TEXT
- `timestamp` DATETIME
- `lat` REAL
- `lon` REAL

### Migration strategy

Drift schema v2 to v3. `ALTER TABLE ADD COLUMN` for each new field with defaults. New table creation for BoundaryEvents.
